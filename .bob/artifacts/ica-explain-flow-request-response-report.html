Key discovery: "Exam Explainer Agent" lives under /assistants (not /agents). Its resolved UUID is 4b7bbee7-e66d-437c-95c7-556eadaa5ac5. The UUID is cached in memory after the first name lookup, so only one extra GET /assistants round-trip ever happens per process lifetime.

2. Hop 1 — Client → FastAPI POST /ica/explain

Request

{
  "question_id": 180555501,         // required — ID from the JSON file
  "agent": "Exam Explainer Agent",  // optional — defaults to this value
  "max_tokens": null                // optional — null lets ICA use its default
}

What FastAPI does with it

  1. Validates the body against ExplainRequest (Pydantic). question_id must be an integer; 422 if missing.
  2. Looks up the item by question_id in an in-memory dict built from public/claude-certified-architect-practice-1.json. Returns 404 if not found.
  3. Resolves "Exam Explainer Agent" → UUID via GET /assistants (cached after first call).
  4. Builds a plain-text prompt from the item (HTML stripped) and forwards it to ICA.
  5. Parses the ICA response and returns ExplainResponse.

Response

{
  "question_id": 180555501,
  "explanation": "# Understanding the question...\n\n...",  // Markdown string from the agent
  "finish_reason": "stop",
  "total_tokens": 7479,
  "agent_id": "4b7bbee7-e66d-437c-95c7-556eadaa5ac5"
}

Request body

{
  "model": "4b7bbee7-e66d-437c-95c7-556eadaa5ac5",  // assistant UUID — NOT the name
  "messages": [
    {
      "role": "user",
      "content": "Section: Domain 4: Prompt Engineering...\n\nQUESTION:\n...\n\nANSWER CHOICES:\n  A. Have the agent attach...\n  B. Route each proposed...\n  C. Append a follow-up...\n  D. Enable extended thinking...\n\nCORRECT ANSWER: B\n\nPER-CHOICE FEEDBACK:\n  A. Self-reported confidence...\n  B. An independent reviewer...\n  ...\n\nOFFICIAL EXPLANATION:\n...\n\nPlease simplify and explain this question..."
    }
  ],
  "stream": false
  // temperature/top_p intentionally omitted — Claude on ICA only accepts temperature=1
  // max_tokens omitted unless caller passed it (would be bumped +5000 for thinking reserve)
}

Response body (OpenAI-compatible)

{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1715000000,
  "model": "...",
  "choices": [
    {
      "index": 0,
      "finish_reason": "stop",
      "message": {
        "role": "assistant",
        "content": "# Understanding the question in simple terms\n\n..."
      }
    }
  ],
  "usage": {
    "prompt_tokens": 1234,
    "completion_tokens": 987,
    "total_tokens": 7479
  }
}
ICA quirks in play:
  • Browser User-Agent — without it the WAF returns HTTP 403 before the request reaches ICA.
  • No temperature — Claude Opus/Sonnet on ICA only accepts the default (1.0). Sending any temperature causes a 400.
  • +5 000 token reserve — Claude uses extended thinking tokens before emitting the visible reply. Without the reserve, finish_reason is "length" and content is empty.
  • 300 s timeout — large prompts with reasoning can take 60–120 s. Default HTTP timeouts will fire too early.

4. Prompt Structure Sent to ICA

The prompt is assembled from the raw practice-exam item, with HTML stripped. All fields come from the JSON file.

Prompt sectionSource fieldCleaning applied
Section:item.sectionNone
QUESTION:item.prompt.questionclean_question() — strips <p>, converts <pre>/<code>, unescapes HTML entities
ANSWER CHOICES: A–Ditem.prompt.answers[]None (already plain text)
CORRECT ANSWER:item.correct_response[]Uppercased letters (e.g. "B")
PER-CHOICE FEEDBACK:item.prompt.feedbacks[]clean_plain() — HTML unescape only
OFFICIAL EXPLANATION:item.prompt.explanationclean_plain()
Instruction tailHardcoded"Please simplify and explain…"

5. DB Persistence Design (what should go into MongoDB)

The goal is to store the simplified question/answer model alongside the original item. Suggested document shape:

{
  "_id": "180555501",            // question_id as string key
  "source": "claude-certified-architect-practice-1",
  "section": "Domain 4: Prompt Engineering & Structured Output",
  "question_id": 180555501,

  // ── original content (from the JSON file) ──
  "original": {
    "question": "<p>SCENARIO: ...</p>",
    "answers": ["Have the agent...", "Route each...", "Append...", "Enable..."],
    "correct_response": ["b"],
    "explanation": "<p>The core insight...</p>"
  },

  // ── simplified content (from Exam Explainer Agent) ──
  "simplified": {
    "explanation": "# Understanding the question in simple terms\n\n...",  // Markdown
    "finish_reason": "stop",
    "total_tokens": 7479,
    "agent_id": "4b7bbee7-e66d-437c-95c7-556eadaa5ac5",
    "created_at": "2026-10-29T16:48:00Z"
  }
}
Why keep both? The original HTML content is the source of truth for the exam engine. The simplified Markdown is a derived artefact. Storing them in the same document makes it easy to regenerate the simplified version without a second lookup and easy to invalidate it when the source changes.
