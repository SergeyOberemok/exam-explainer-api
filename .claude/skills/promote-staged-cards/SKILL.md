# Promote Staged Cards

`.staging/*.pending.json` (gitignored, regenerated by
`uv run python -m claude_exam.extract public/<name>.json`) holds practice-exam
questions not yet in the vault, already split into `question`/`answer`/`explanation`/
`references`/`folder` fields by the extract pipeline (see `CLAUDE.md`). This skill is
the missing last step: turning one pending record into a real card under
`Questions/<folder>/`, in the vault's exact card format — and making sure the two
retrofit skills (`roadmap-linker`, `keyword-highlighter`) run on it immediately, rather
than depending on a later pass to notice it was skipped.

## When to run this

- The user asks to add/promote some or all pending questions from a
  `.staging/*.pending.json` file.
- The user hands you a single staged record (or its `id`) to turn into a card.
- Regenerate the staging file first if it might be stale:
  `uv run python -m claude_exam.extract public/<name>.json` (it already skips anything
  matching an existing card, via `find_existing`).

## Step 1 — read the record(s)

Each pending record already has: `id`, `section`, `folder` (a `Questions/` subfolder
name), `question`, `answer`, `explanation`, `references` (a list, often empty). None of
this is your choice to change — the extract pipeline already cleaned the HTML and
picked the correct answer/explanation text; don't reword it while drafting the card.

## Step 2 — draft the card

For each record, create `Questions/<folder>/<Title>.md` (`<folder>` is the record's
`folder` field; only deviate from it if the content is clearly filed wrong) following
the exact structure in `Templates/Question_Template.md` plus the hand-added frontmatter
and heading (per `CLAUDE.md`'s "Question card format"):

```
---
tags:
  - <topic-slug>
  - <keyword-slug>
  - ...
---

# <Title>

### Question
<record.question>
### Answer
<record.answer>
##### Explanation
<record.explanation>
##### References
<record.references, one per line each ending in a trailing double-space/line-break>
```

Two things need human judgment here, same as for any hand-authored card:
- **Title** — a short scenario-style title matching the vault's existing naming
  convention (e.g. "Fixing tool_result Ordering and Mismatched tool_use_id",
  "Placing Long Documents Before the Query in Long-Context Prompts") — descriptive of
  the specific defect/decision, not a restatement of the section name. Becomes both the
  `# <Title>` heading and the filename.
- **Tags** — kebab-case topic + keyword slugs; reuse existing tags across the vault
  where the topic overlaps (grep existing frontmatter for related terms) rather than
  inventing near-duplicates.

If `record.references` is empty, leave the References section otherwise blank for now —
Step 3 supplies the `Roadmap: [[...]]` line regardless.

## Step 3 — close the loop: roadmap-linker + keyword-highlighter

Do not stop after drafting. For every card just created, in order:

1. Invoke the `roadmap-linker` skill on it — adds the `Roadmap: [[...]]` line to
   References and, where warranted, a roadmap-derived tag.
2. Invoke the `keyword-highlighter` skill on it — adds sparing `==highlight==` markup
   correlating the Question's decisive fact to the resolving phrase in Answer/
   Explanation.

Do this per card as you draft it, or as a batch afterward across every card drafted in
this run — either way, no newly-promoted card should be left without both passes
applied before you report the promotion as done.

## Step 4 — report

State which pending record(s) were promoted (`id` → new file path), which were skipped
and why (e.g. looked like a near-duplicate of an existing card, or the folder didn't
fit), and confirm both follow-up skills ran on each new file.

## Constraints

- Never alter `record.question`/`answer`/`explanation` wording while drafting — only
  reformat into the card skeleton.
- Don't invent a `folder` other than the record's own unless it's clearly wrong for the
  content.
- Always follow through with `roadmap-linker` and `keyword-highlighter` on every card —
  that hand-off is the reason this skill exists, not an optional extra.
